# Spring循环依赖解决机制详解

## 🎯 核心概念

循环依赖（Circular Dependency）是指两个或多个Bean之间相互依赖，形成闭环的情况。

**示例**：
```java
@Service
public class ServiceA {
    private final ServiceB serviceB;

    public ServiceA(ServiceB serviceB) {
        this.serviceB = serviceB;
    }
}

@Service
public class ServiceB {
    private final ServiceA serviceA;

    public ServiceB(ServiceA serviceA) {
        this.serviceA = serviceA;
    }
}
```

**Spring的解决策略**：
- ✅ **支持单例Bean的setter注入和字段注入**
- ❌ **不支持原型Bean（prototype）的循环依赖**
- ❌ **不支持构造器注入的循环依赖**

### 类型1：自身依赖

```java

    @Autowired
```

### 类型2：双向依赖

```java

    private ServiceB serviceB;
```

### 类型3：多边依赖

```java
@Service
public class ServiceA {
    @Autowired
    private ServiceB serviceB;

@Service
public class ServiceB {
    @Autowired
    private ServiceC serviceC;
}

@Service
public class ServiceC {
    @Autowired
    private ServiceA serviceA;
}
```

### 类型4：构造器循环依赖

```java
@Service
public class ServiceA {
    private final ServiceB serviceB;

    public ServiceA(ServiceB serviceB) {
        this.serviceB = serviceB;
    }
}

@Service
public class ServiceB {
    private final ServiceA serviceA;

    public ServiceB(ServiceA serviceA) {
        this.serviceA = serviceA;
    }
}
```

**结果**：抛出`BeanCurrentlyInCreationException`

## 🔑 Spring的三级缓存机制

### 三级缓存的结构

Spring使用**三级缓存**来解决循环依赖问题：

```java
// DefaultSingletonBeanRegistry.java
public class DefaultSingletonBeanRegistry {

    // 一级缓存：完整的Bean实例（已初始化）
    private final Map<String, Object> singletonObjects = new ConcurrentHashMap<>(256);

    // 二级缓存：早期暴露的Bean（已实例化，未初始化）
    private final Map<String, Object> earlySingletonObjects = new ConcurrentHashMap<>(16);

    // 三级缓存：Bean工厂（用于创建早期暴露的Bean或代理对象）
    private final Map<String, ObjectFactory<?>> singletonFactories = new HashMap<>(16);

    // 正在创建中的Bean名称集合
    private final Set<String> singletonsCurrentlyInCreation = Collections.newSetFromMap(new ConcurrentHashMap<>(16));
}
```

### 三级缓存的职责

| 级别 | 缓存名称 | 作用 | 存放内容 |
|------|---------|------|---------|
| **一级缓存** | singletonObjects | 存放完整的Bean实例 | 已完成实例化和初始化的Bean |
| **二级缓存** | earlySingletonObjects | 存放早期暴露的Bean | 已实例化但未初始化的Bean |
| **三级缓存** | singletonFactories | 存放Bean工厂 | 可以创建Bean实例或代理对象的工厂 |

```
   ↓

      addSingletonFactory("serviceB", () -> getEarlyBeanReference("serviceB", mbd, bean))

   ↓

      populateBean()
      ↓
      发现需要注入serviceA

      getBean("serviceA")
      ↓
      【再次请求serviceA】
      ↓
      1. getBean("serviceA")
      ↓
      2. ⭐️ 先从缓存中获取Bean（关键步骤）
         getSingleton("serviceA")
```

## 🔑 关键源码分析

### 方法1：getBean() - 获取Bean

**位置**：`AbstractBeanFactory.java:256`

```java
public Object getBean(String name) throws BeansException {

}
```

### 方法2：doGetBean() - 获取Bean的核心逻辑

**位置**：`AbstractBeanFactory.java:272`

```java
protected <T> T doGetBean(
    String name, @Nullable Class<T> requiredType, @Nullable Object[] args, boolean typeCheckOnly) {

    // 1. 转换Bean名称（处理&前缀、别名等）
    String beanName = transformedBeanName(name);

    // 2. ⭐️ 先从缓存中获取Bean
    Object sharedInstance = getSingleton(beanName);
    if (sharedInstance != null && args == null) {
        // 如果缓存中存在，直接返回
        return (T) getObjectForBeanInstance(sharedInstance, name, beanName, null);
    }

    // 3. 检查是否正在创建
    if (isPrototypeCurrentlyInCreation(beanName)) {
        throw new BeanCurrentlyInCreationException(beanName);
    }

    // 4. 标记Bean正在创建
    if (!typeCheckOnly) {
        markBeanAsCreated(beanName);
    }

    try {
        // 5. 创建Bean实例
        BeanDefinition mbd = getMergedLocalBeanDefinition(beanName);
        String[] dependsOn = mbd.getDependsOn();
        // 处理depends-on依赖

        // 6. ⭐️ 创建Bean实例
        if (mbd.isSingleton()) {
            sharedInstance = getSingleton(beanName, () -> {
                try {
                    return createBean(beanName, mbd, args);
                } catch (BeansException ex) {
                    destroySingleton(beanName);
                    throw ex;
                }
            });
        }
    } catch (BeansException ex) {
        cleanupAfterBeanCreationFailure(beanName);
        throw ex;
    }

    return (T) getObjectForBeanInstance(sharedInstance, name, beanName, requiredType);
}
```

### 方法3：getSingleton() - 从缓存获取Bean

**位置**：`DefaultSingletonBeanRegistry.java:234`

```java
@Nullable
protected Object getSingleton(String beanName, boolean allowEarlyReference) {
    // 1. ⭐️ 从一级缓存获取（完整的Bean）
    Object singletonObject = this.singletonObjects.get(beanName);
    if (singletonObject == null) {
        // 2. 如果一级缓存没有，且Bean正在创建中
        if (this.singletonsCurrentlyInCreation.contains(beanName)) {
            synchronized (this.singletonObjects) {
                // 3. ⭐️ 从二级缓存获取（早期暴露的Bean）
                singletonObject = this.earlySingletonObjects.get(beanName);
                if (singletonObject == null && allowEarlyReference) {
                    // 4. ⭐️ 从三级缓存获取（Bean工厂）
                    ObjectFactory<?> singletonFactory = this.singletonFactories.get(beanName);
                    if (singletonFactory != null) {
                        // 5. 调用Bean工厂获取Bean
                        singletonObject = singletonFactory.getObject();
                        // 6. ⭐️ 从三级缓存移动到二级缓存
                        this.earlySingletonObjects.put(beanName, singletonObject);
                        this.singletonFactories.remove(beanName);
                    }
                }
            }
        }
    }
    return singletonObject;
}
```

### 方法4：addSingletonFactory() - 添加Bean工厂到三级缓存

**位置**：`DefaultSingletonBeanRegistry.java:198`

```java
protected void addSingletonFactory(String beanName, ObjectFactory<?> singletonFactory) {
    synchronized (this.singletonObjects) {
        if (!this.singletonObjects.containsKey(beanName)) {
            // ⭐️ 添加到三级缓存
            this.singletonFactories.put(beanName, singletonFactory);
            // 从二级缓存移除（如果存在）
            this.earlySingletonObjects.remove(beanName);
        }
    }
}
```

### 方法5：getEarlyBeanReference() - 获取早期引用

**位置**：`AbstractAutowireCapableBeanFactory.java:2038`

```java
protected Object getEarlyBeanReference(String beanName, RootBeanDefinition mbd, Object bean) {
    Object exposedObject = bean;

    // ⭐️ 检查是否需要AOP代理
    if (!mbd.isSynthetic() && hasInstantiationAwareBeanPostProcessors()) {
        for (BeanPostProcessor bp : getBeanPostProcessors()) {
            if (bp instanceof SmartInstantiationAwareBeanPostProcessor) {
                SmartInstantiationAwareBeanPostProcessor ibp =
                    (SmartInstantiationAwareBeanPostProcessor) bp;
                exposedObject = ibp.getEarlyBeanReference(exposedObject, beanName);
                // ⭐️ 如果有AOP代理，这里会返回代理对象
            }
        }
    }
    return exposedObject;
}
```

## 🔑 为什么需要三级缓存？

### 为什么二级缓存不够？

**问题场景**：AOP代理

```java
@Service
public class ServiceA {
    @Autowired
    private ServiceB serviceB;

    @Transactional
    public void methodA() {
        // ...
    }
}

@Service
public class ServiceB {
    @Autowired
    private ServiceA serviceA;
}
```

**分析**：

如果只用二级缓存：
1. 创建ServiceA实例（原始对象）
2. 暴露到二级缓存：`earlySingletonObjects.put("serviceA", 原始对象)`
3. 填充serviceB，创建ServiceB
4. ServiceB需要注入serviceA
5. 从二级缓存获取serviceA：**获取的是原始对象**
6. ServiceB持有原始对象的引用
7. ServiceA初始化完成，创建AOP代理
8. **问题**：ServiceB持有的是原始对象，不是代理对象！

使用三级缓存：
1. 创建ServiceA实例（原始对象）
2. 暴露到三级缓存：`singletonFactories.put("serviceA", ObjectFactory)`
3. 填充serviceB，创建ServiceB
4. ServiceB需要注入serviceA
5. 从三级缓存获取serviceA：
   - 调用`ObjectFactory.getObject()`
   - 调用`getEarlyBeanReference()`
   - **检查是否需要AOP代理**
   - 如果需要：返回代理对象
6. ServiceB持有代理对象的引用
7. ServiceA初始化完成，使用相同的代理对象
8. ✅ 正确！

### 三级缓存的核心作用

三级缓存的核心作用是：**延迟代理对象的创建时机**

- **不在实例化时立即创建代理**（性能考虑）
- **在第一次被引用时才创建代理**（按需创建）
- **确保所有引用都指向同一个代理对象**

## 🎯 不同注入方式的循环依赖

### 1️⃣ Setter注入 - ✅ 支持

```java
@Service
public class ServiceA {
    @Autowired
    private ServiceB serviceB;
}

@Service
public class ServiceB {
    @Autowired
    private ServiceA serviceA;
}
```

**结果**：✅ 成功解决

**原因**：
- 可以先实例化，再注入
- 早期引用可以暴露给其他Bean

### 2️⃣ 字段注入 - ✅ 支持

```java
@Service
public class ServiceA {
    @Autowired
    private ServiceB serviceB;
}

@Service
public class ServiceB {
    @Autowired
    private ServiceA serviceA;
}
```

**结果**：✅ 成功解决

**原因**：
- 字段注入本质上是setter注入
- 可以先实例化，再注入

### 3️⃣ 构造器注入 - ❌ 不支持

```java
@Service
public class ServiceA {
    private final ServiceB serviceB;

    public ServiceA(ServiceB serviceB) {
        this.serviceB = serviceB;
    }
}

@Service
public class ServiceB {
    private final ServiceA serviceA;

    public ServiceB(ServiceA serviceA) {
        this.serviceA = serviceA;
    }
}
```

**结果**：❌ 抛出`BeanCurrentlyInCreationException`

**原因**：
- 构造器注入要求在实例化时就提供依赖
- 无法先实例化，再注入
- 形成死锁

### 4️⃣ 原型Bean（Prototype）- ❌ 不支持

```java
@Scope("prototype")
@Service
public class ServiceA {
    @Autowired
    private ServiceB serviceB;
}

@Scope("prototype")
@Service
public class ServiceB {
    @Autowired
    private ServiceA serviceA;
}
```

**结果**：❌ 抛出`BeanCurrentlyInCreationException`

**原因**：
- 原型Bean不缓存
- 每次请求都创建新实例
- Spring不会管理原型Bean的完整生命周期

## 💡 解决循环依赖的方法

### 方法1：使用@Lazy注解（推荐）

```java
@Service
public class ServiceA {
    private final ServiceB serviceB;

    public ServiceA(@Lazy ServiceB serviceB) {
        this.serviceB = serviceB;
    }
}

@Service
public class ServiceB {
    private final ServiceA serviceA;

    public ServiceB(ServiceA serviceA) {
        this.serviceA = serviceA;
    }
}
```

**原理**：
- `@Lazy`会注入一个代理对象
- 真正的Bean在第一次调用时才创建
- 打破了循环依赖链

### 方法2：使用Setter注入或字段注入

```java
@Service
public class ServiceA {
    @Autowired
    private ServiceB serviceB;
}

@Service
public class ServiceB {
    @Autowired
    private ServiceA serviceA;
}
```

### 方法3：使用@PostConstruct初始化

```java
@Service
public class ServiceA {
    @Autowired
    private ServiceB serviceB;
}

@Service
public class ServiceB {
    private ServiceA serviceA;

    @Autowired
    public void setServiceA(ServiceA serviceA) {
        this.serviceA = serviceA;
    }
}
```

### 方法4：重构设计（最佳实践）

```java
// 提取公共接口
public interface Service {
    void execute();
}

@Service
public class ServiceA implements Service {
    @Autowired
    private ServiceCommon serviceCommon;

    @Override
    public void execute() {
        serviceCommon.executeA();
    }
}

@Service
public class ServiceB implements Service {
    @Autowired
    private ServiceCommon serviceCommon;

    @Override
    public void execute() {
        serviceCommon.executeB();
    }
}

@Service
public class ServiceCommon {
    public void executeA() {
        // ...
    }

    public void executeB() {
        // ...
    }
}
```

## 🎯 总结

### 核心要点

1. ✅ **Spring使用三级缓存解决循环依赖**
   - 一级缓存：完整的Bean实例
   - 二级缓存：早期暴露的Bean
   - 三级缓存：Bean工厂

2. ✅ **三级缓存的核心作用**：
   - 延迟代理对象的创建时机
   - 确保所有引用都指向同一个代理对象

3. ✅ **支持的循环依赖**：
   - ✅ 单例Bean的setter注入
   - ✅ 单例Bean的字段注入
   - ❌ 构造器注入
   - ❌ 原型Bean

4. ✅ **解决循环依赖的方法**：
   - 使用@Lazy注解
   - 使用Setter注入或字段注入
   - 重构设计，消除循环依赖

### 设计模式

- **模板方法模式**：getBean()定义获取Bean的流程
- **工厂模式**：三级缓存使用ObjectFactory创建Bean
- **代理模式**：AOP代理解决循环依赖中的代理对象问题
